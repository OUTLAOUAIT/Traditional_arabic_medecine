# Traditional Arabic Medicine Text Pipeline

This project retrieves the Arabic Wikisource article *الطب النبوي*, splits its paragraphs into fasls and retrieval chunks, stores source records in MongoDB, and generates BGE-M3 vectors for Weaviate.

## Architecture

- **MongoDB** stores the original fasls and generated chunks.
- **Python and BAAI/bge-m3** generate dense embeddings. The model runs where the Python script runs (your computer or Google Colab).
- **Weaviate Cloud** stores vectors and searchable chunk metadata/text. Local Docker Weaviate remains available for development.

## Requirements

- Python 3.10 or newer
- A MongoDB instance reachable from the machine running ingestion
- A Weaviate Cloud cluster, or Docker Desktop with Docker Compose for local Weaviate
- Network access to Wikisource and Hugging Face

Create and activate a virtual environment, then install the packages:

```powershell
py -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

On macOS or Linux, activate the environment with `source .venv/bin/activate`.

## Configuration

Copy `.env.example` to `.env` and set your MongoDB URI. `.env` is ignored by Git.

```powershell
Copy-Item .env.example .env
```

| Variable | Purpose |
| --- | --- |
| `MONGODB_CONNECTION_STRING` | MongoDB connection URI |
| `DATA_BASE` | MongoDB database name |
| `COLLECTION_NAME` | Fasls collection name |
| `CHUNKS_COLLECTION_NAME` | MongoDB chunks collection; defaults to `chunks` |
| `WEAVIATE_COLLECTION_NAME` | Weaviate collection; defaults to `TibbChunksBgeM3` |
| `WEAVIATE_URL` | Weaviate Cloud REST endpoint. Leave blank to use local Docker. |
| `WEAVIATE_API_KEY` | Weaviate Cloud API key. Leave blank to use local Docker. |
| `EMBEDDING_MODEL_NAME` | Embedding model; defaults to `BAAI/bge-m3` |
| `EMBEDDING_BATCH_SIZE` | Embedding batch size; defaults to `8` |

### Use Weaviate Cloud

In the Cloud Console, open your cluster and copy its **REST Endpoint** and create/copy an API key. Put them in `.env` as `WEAVIATE_URL` and `WEAVIATE_API_KEY`. Keep the key private; do not commit `.env` or paste the key into source code.

The app uses Cloud automatically when both variables are set. The collection is created with a self-provided `dense` vector, so BGE-M3 embeddings are generated by Python and are not sent to Weaviate's hosted embedding service. The free cluster currently allows one collection and 100,000 objects. It suspends after 7 days without activity and may be deleted after 30 days of total inactivity; reactivate it in the console if suspended.

Before ingestion, check that the Cloud cluster is ready:

```powershell
python -c "from src.weaviate_connection import connect_weaviate; c=connect_weaviate(); print('ready:', c.is_ready()); c.close()"
```

If it prints `ready: False`, check the cluster status and endpoint/key in the Cloud Console. Your MongoDB must also be reachable from the environment running ingestion. In Colab, add MongoDB credentials, `WEAVIATE_URL`, and `WEAVIATE_API_KEY` to Colab Secrets; do not put secrets in a notebook shared publicly. The BGE-M3 model is downloaded and run in the Colab runtime, so its temporary disk and session lifetime still apply.

### Use local Docker instead

Leave both Weaviate Cloud variables blank. Then start the included local service:

```powershell
docker compose up -d
docker compose ps
```

## Scrape the Wikisource article

The scraper retrieves article paragraphs and headings through the MediaWiki API and writes UTF-8 text separated by blank lines:

```powershell
python scrape_wikisource.py "https://ar.wikisource.org/wiki/الطب_النبوي" data/raw_data.txt
```

The raw corpus is a local input file and is excluded by `.gitignore`; create it with the scraper after cloning the repository.

## Split and save fasls

`src/data_processing.py` splits `data/raw_data.txt` at paragraph starts matching Arabic section headings. It keeps a normalized search copy, counts Arabic word and punctuation tokens with PyArabic, and builds Wikisource URLs.

```powershell
python -c "from src.data_processing import split_raw_data_file, save_fasls_to_mongodb; fasls = split_raw_data_file(); print(save_fasls_to_mongodb(fasls))"
```

## Create MongoDB retrieval chunks

Download the BGE-M3 tokenizer once, then generate chunks from the MongoDB fasls collection:

```powershell
python -c "from transformers import AutoTokenizer; AutoTokenizer.from_pretrained('BAAI/bge-m3', use_fast=True)"
python -m src.chunking
```

Chunking counts the complete embedding input (`title + blank line + text`) and enforces a 2,048-token maximum. It groups whole consecutive paragraphs, permits shorter chunks when the next paragraph will not fit, and overlaps with complete trailing paragraphs where they fit. An oversized paragraph raises an error rather than being split. Each fasl produces at least one chunk. MongoDB chunks are upserted using a unique compound index on `(fasl_id, chunking_version, chunk_index)`.

## Create the Weaviate collection and ingest vectors

The collection uses a self-provided named vector called `dense`. Cloud free clusters enforce their Cost Optimized index settings; local Weaviate uses its default index.

```powershell
python setup_weaviate.py
python -m src.weaviate_store
```

The first run downloads the BGE-M3 weights from Hugging Face (about 2.27 GB). Later runs reuse the local model cache. Stable Weaviate UUIDs make reruns replace matching objects instead of creating duplicates. MongoDB remains the source of truth.

## Search Weaviate

```python
from src.weaviate_store import search_chunks

results = search_chunks("كيف يكون التداوي مع القدر؟", limit=5)
for result in results:
    print(result["title"], result["distance"])
    print(result["text"])
```

By default, search returns at most one (the closest) chunk per fasl, so results cover more sections. Pass `unique_fasls=False` to allow multiple chunks from the same fasl. To run the 18-query Arabic retrieval review and inspect its title matches and text excerpts, run:

```powershell
python -m src.retrieval_eval
```

## Generate answers with Gemini in Colab

The Colab notebook can now answer questions using retrieved Weaviate chunks as its only context. It uses `gemini-3.8-flash` by default and returns source IDs with the matching fasl titles and Wikisource URLs.

For Colab, add a secret named `GEMINI_API_KEY` in the notebook's Secrets panel and enable notebook access. Optionally add `GEMINI_MODEL_NAME`; it defaults to `gemini-3.8-flash`. The same variables are listed in `.env.example` for local configuration. The free API tier has quotas and separate data-use terms; do not send private material through it. The notebook does not use Google Search grounding.

Run the RAG function cell after the retrieval setup, then run the example question cell. Call `answer_question("your question")` to retrieve and synthesize an answer. The answer includes inline `[S1]`-style citations; the returned `sources` list maps each citation to its title, URL, and chunk index.


## Run the Streamlit app

The app answers questions using the existing Weaviate vectors and Gemini. Bulk ingestion stays in Colab; the app only embeds each question and loads BGE-M3 once per app process.

Run locally after configuring `.env`:

```powershell
streamlit run app.py
```

For Streamlit Community Cloud, deploy `app.py` from this GitHub repository and add these values in the app's Secrets settings:

```toml
WEAVIATE_URL = "https://your-cluster.weaviate.network"
WEAVIATE_API_KEY = "your-weaviate-api-key"
WEAVIATE_COLLECTION_NAME = "TibbChunksBgeM3"
GEMINI_API_KEY = "your-gemini-api-key"
GEMINI_MODEL_NAME = "gemini-3.8-flash"
EMBEDDING_MODEL_NAME = "BAAI/bge-m3"
```

Do not commit `.streamlit/secrets.toml`. Community Cloud's documented memory ceiling is approximately 2.7 GB, so BGE-M3 inference may exceed the free app's resources; check the app logs if startup or first-question inference fails. If that happens, move query embedding to a service with more memory while keeping the Streamlit UI and existing Weaviate/Gemini flow.
